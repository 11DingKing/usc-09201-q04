# 林权融资占用监测领域约定

项目面向集体林权改革与林下产业协作场景，围绕同一本经营权证可能被多家金融机构重复占用的风险，
把“登记 → 估值 → 冻结授信 → 分期提款 → 偿还 → 解除/释放”做成一条只增不改、可重放重算的事件链。

## 角色与数据可见性

- `registrar` 林权登记机构：登记权证范围与地块权重，发布估值版本，对地块释放出具回执。
- `institution` 金融机构（按 `institutionId` 区分，如 BANK_A / BANK_B）：冻结授信、提款、还款、
  申请撤销/释放、对他方释放出具回执。
- `regulator` 金融监管协作方：查看全量明细、事件日志，并可随时发起重算审计。

机构只看得到自有授信的完整字段；权证上属于他人的地块只显示 `encumbered`，
看不到持有方、额度与余额。估值版本历史、全量回执与事件日志仅监管可见。

## 事件类型（只追加，哈希链串联）

| 事件 | 含义 |
| --- | --- |
| `certificate.registered` | 登记权证、地块清单、地块权重与初始估值版本 |
| `valuation.recorded` | 估值新版本（版本号唯一，不覆盖历史版本） |
| `facility.frozen` | 机构就一组地块冻结授信额度 |
| `drawdown.made` | 授信项下一笔提款 |
| `repayment.recorded` | 还款及按 FIFO 落账次序固化的提款冲抵分配 |
| `revocation.requested` / `cancelled` / `facility.revoked` | 撤销申请、撤回、结清后解除 |
| `release.requested` / `receipt.recorded` / `release.approved` / `release.rejected` | 部分地块释放与多方回执 |
| `command.rejected` | 被规则拒绝的命令同样留痕（含冲突原因与细节） |

每个事件含 `seq / ts / type / certificateId / data / hash`，`hash = sha256(prevHash | 稳定序列化事件体)`，
首事件前链值为 64 个 0。任一历史事件被篡改都会导致链校验断裂。

## 占用与余量规则

- 同一地块同一时点只能被一笔有效授信冻结；并发冻结按**权证串行队列的提交次序**确定赢家，
  后者收到 409 `parcel_already_encumbered` 并写入 `command.rejected`。
- 授信额度不得超过其地块按当前估值分摊的覆盖价值；全权证冻结总额不得超过权证估值。
- 提款同时受授信额度与地块覆盖价值约束；估值下调后，存量余额不被抹除（以 `coverageShortfall` 暴露缺口），
  但超额新提款按当前估值版本拒绝（`insufficient_coverage`）。
- 还款（含提前还款）按提款 FIFO 冲抵，分配方案随还款事件固化，重放时不重新分配。
- 撤销申请后、最终解除前的新提款一律拒绝（`revocation_in_progress`）；撤销可撤回；
  只有余额结清才允许最终解除、地块回归权证。
- 部分地块释放需取得**确定回执集合**（登记机构 + 权证上其他授信机构，按机构去重）。
  回执可乱序到达，集齐时才决策：任一拒绝即整体拒绝；全部同意时再按当时估值复核覆盖，
  复核通过才移除地块并把授信额度下调至与剩余覆盖一致。

## 可重算性

活动状态是事件日志的即时投影（`src/domain/projection.mjs` 的 `fold`）。
监管通过 `POST /regulator/recompute` 从空状态重放全部事件，逐权证比较活动余量与重放余量，
并比较完整状态快照；重算必须返回 `stateMatches: true`、每个权证 `match: true`。
冲突响应、回执次序、撤销拦截全部是日志事实，审计结论可随时复现。

## 确定性与重试

- 同一权证的命令经异步锁串行化，进程内提交次序即事件 `seq` 次序，重放结果与运行时一致。
- 写命令支持 `Idempotency-Key` 头（按调用方隔离）：重试返回首次结果，不产生第二笔占用。
